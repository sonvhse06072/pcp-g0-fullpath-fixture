# F2-T01 — Crossing-midnight interval overlap (FUTURE WorkOrder)

**Status:** ACCEPTANCE PROPOSAL ONLY. Not implemented by the initial baseline. PCP canonical G0-02 [#595](https://github.com/sonvhse06072/personal-coding-platform/issues/595).

## Scope

Use the existing Drupal 11 `pcp_f2_fixture.window_overlap` service and `WindowOverlapDetector::intersects(int, int, int, int): bool` contract. Do not add new dependencies, tables, persistent users, storage, routes, cron, background services or model-provider integrations.

The original baseline handles same-day **half-open intervals** correctly. The new task adds support for windows that cross midnight, using minute values within a 24-hour clock. Inputs: `start` must be in [0, 1439], `end` in [0, 1440]. If `end < start`, the window spans midnight (e.g. 1380→60 means [23:00, 01:00)). If `end == start`, consider it an invalid/empty interval, **not** a 24-hour all-day window. Standard intervals with end 1440 terminate at midnight.

**Acceptance:** correctly detect overlap on the 24-hour cycle while retaining half-open endpoint semantics and symmetry of the two windows. In particular:

- (1380, 60) vs (30, 90) → TRUE, and reversed order TRUE.
- (1380, 60) vs (1320, 1380) → FALSE (touching at 23:00 only).
- (1380, 60) vs (60, 120) → FALSE (touching at 01:00 only).
- (1380, 60) vs (0, 15) → TRUE.
- (540, 600) vs (600, 660) → FALSE (existing rule).
- End equals start or either endpoint outside its allowed range → FALSE.

Modify **at most** `WindowOverlapDetector.php`, the matching Unit test and matching Drupal Kernel test. Require PHP syntax + Drupal PHPCS + locked Composer + Unit and Kernel tests. Changes delivered only through `ai/*` PR with exact-HEAD GitHub-hosted `validation` and PM review; no direct push to seed/main and no forced merge.
